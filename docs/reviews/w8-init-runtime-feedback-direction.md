# W8: truthful runtime preview, confirmation and completion

W7 choices/navigation are accepted. Correct the gap between init's final confirmation and the actions it actually performs. Current human confirmation says external actions remain pending, but default apply subsequently installs/binds the current package runtime outside the workspace. Completion and pending copy also mixes internal milestones with provider/index preferences. Reuse existing runtime install/binding/ownership primitives; do not introduce another executor or change privacy/config schemas.

## Preview and action agreement

Build a small UI-independent operation description from the actual init options, resolved root, bundle and existing runtime path helpers. Human plan must distinguish workspace config writes, durable runtime operation and separately deferred preferences. With default runtime enabled, state current-package/self source and exact target version/user-data runtime directory plus local machine binding. Explicit tarball/version modes must identify the actual source (tarball path or exact package version, including possible package-manager/network work) and target. `--no-runtime` must explicitly say no runtime operation will run. Resolve paths using the same environment/data-directory logic as execution; never guess a conventional home path.

Read-only preview/choices must not install, pack, run smoke/version probes, create runtime state, acquire locks or write config. Existing passive observations may establish present/unknown state, not verified execution. An apply can reuse a verified runtime, but a preview must not promise reuse solely from a regular executable file. Account for already configured/no-config-change cases: `--apply` may still perform runtime work; no automatic execution from an empty read-only plan.

Before any interactive mutation, the final prompt accurately names the actions this invocation will attempt and what remains deferred. Retain false/default cancellation. Explicit `--apply` remains the existing non-prompt authorization path. Config-only `--config` without --apply stays read-only even in a TTY. Selection review is not apply consent. Runtime failure never retroactively makes applied config disappear; report both actual config outcome and runtime failure/residuals.

## Completion meaning

Summarize configuration applied/reused, runtime installed/reused/bound or intentionally deferred/failed, knowledge registration not performed by init, code indexing/provider preparation not performed, and host declaration versus integration. Optional unselected capabilities are not failures. Selected but deferred optional preferences get accurate next actions; do not claim they were installed/prepared/verified, or make core setup success depend on unselected work. Remove P03/P04 from init human preview/apply/completion copy. Avoid contradictory intermediate messages saying runtime remains pending after it was executed or claiming default-self is an explicit tarball request.

Keep current public JSON fields and schema versions; use existing ok/initComplete/apply/runtime/nextActions/diagnostics meaning. Human success/failure must agree with machine result for the same operation. Any required semantic wire change needs a concrete compatibility proposal before implementation. Do not add a general capability/status schema to solve copy. In particular, a merely existing bound executable is not evidence of a verified durable runtime: inspect the current ensureDefaultRuntime shortcut and ensure completion is supported by the established runtime verification/reuse flow. Reuse its helpers rather than duplicating installer verification. Report necessary scope expansion before editing install/runtime internals.

Init's existing configured/new-source distinction and private-list next action remain clear. Onboard/doctor/docs are consistency references; change their source only for a concrete shared-result disagreement, with scope reported first. Do not broaden this into host/native lifecycle or a storage refactor. Real arbitrary new path selection remains a separate pending bounded-discovery item.

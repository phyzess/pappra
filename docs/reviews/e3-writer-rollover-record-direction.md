Exact writable files: new `src/collab/rollover.ts`, `src/collab/types.ts`, `src/collab/validation.ts`, `src/collab/index.ts`, new `tests/collab/rollover.test.ts`. No other product files. Original Pi owns the existing collab scope; the other visible Pi investigates host controls read-only.

Keep collab core free of filesystem/native/continuity-service dependencies. Do not import verifyHandoffBundle into the reducer, launch a process or implement another task store. The caller will verify a pinned E3-A bundle and actual native/readiness evidence through later app integration. Core records explicit references and validates record/message correlation; supplied observations are never advertised as independently authenticated native proof.

Use a bounded optional typed collection in the existing TaskRecord to retain immutable intent inputs and old/successor native identity links. No separate authority store: handoff state and claims remain authoritative. Intents bind task, handoff ID, source/current attempt and input revision, coordinator epoch, old and successor identity, explicit generation, exact claim IDs/resource epochs and bundle ref/digest. Reject malformed/oversized inputs and invalid record shape conservatively. Reject same-id/different-input conflict, competing live intent for the same writer/resources and closed-intent reopening; exact replay returns existing progress without another mutation. Keep deterministic serialization/digests or a canonical immutable-input comparison. Do not duplicate/advance the existing handoff state independently. No launch retry is authorized by a replay; unknown launch outcome requires reconciliation by a later adapter.

Before beginning, require active current writer ownership/native-session match, current coordinator epoch and all selected active claims held by the source with matching resource epochs. Preserve existing stop/inventory/ownership-drift requirements. Unknown stop/pending-tool or approval completeness must never authorize transfer. Writer transfer raises resource epochs and assignee, not coordinator owner_epoch. Do not call upsertAssignment after transfer (it would replace assignment state); preserve existing attempt input/results/history. Rebinding native identity must be explicit and associated with the observed successor, not inherited from the old native pointer.

Expose a small coherent API for intent creation/inspection, guarded receiver confirmation, transfer completion and first-work/history-link recording, wrapping the existing primitives where useful. Require complete registered stored ACK envelope evidence (validateEnvelope/contentDigest against record.messages), exact task/attempt/input/generation/handoff/source-successor/coordinator correlation and current pre-transfer state. Wrong/missing/reordered/old ACK must fail even if low-level confirmReceiver alone would accept it. Confirmation must not grant execution before the existing completed transfer.

First-work proof requires a fully validated stored successor REPORT and an authoritative applied result for the current input/attempt, correlated to this handoff/generation and registered after the recorded transfer boundary. Sender must equal successor/current assignee, and ownership/native/claim epochs must still agree. Reject historical, pre-transfer, stale_sender, failed/unknown/late/superseded or mismatched evidence. Use record/application ordering or an explicit captured boundary, not sender-created timestamps. Replaying an already recorded valid first-work proof is idempotent; an arbitrary duplicate old result cannot establish a new proof.

Only after that proof may the old native identity receive a retained-history archive marker and durable successor link. The reassigned attempt represents the successor and must never be marked archived. Native archive remains unavailable. Actual routing consumers are outside this five-file scope, so do not claim `routing_removed:true` or effective route removal: represent that integration as pending/unknown explicitly. Restoring history metadata cannot restore resource authority or active routing. No old writer resume/rollback after transfer; recovery observes current record and epochs.

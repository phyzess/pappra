## 2. Evaluate the graph independently of input ordering

Evaluate validated dependencies recursively/topologically with memoized current facts; presentation order must not affect readiness. A blocked/stale/failed predecessor cannot unlock descendants even with an old acceptance.

Wrong-task snapshots currently add a limit but return ready. A node's own failed/cancelled/needs-input state falls through to ready, enabling an accidental retry. Null input revisions are treated as matches. An old exact attempt can remain usable even if a newer attempt exists because supersession is checked only when the exact attempt is absent. Plan evaluation never performs implicit retry or treats frozen/uncertain authority as dispatch readiness.

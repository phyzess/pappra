## User behavior

The picker must offer an explicit Add existing repository / Add existing knowledge file or folder action. Navigation uses actions, not magic path strings. Explain the resolved workspace root and that only the entered location is inspected. Return field-local diagnostics/correction/cancel without losing the draft. Empty existing knowledge folders are legitimate sources; future new-document destination remains a separate setting and is not an implicit source addition. Newly added knowledge paths do not register/copy/move documents. Existing configured unavailable values retain W6 behavior, distinct from a newly entered path that fails inspection.

After a successful bounded inspection, the new candidate is selectable, is included in retained Back/edit/review state and is validated by final app planning. Explicit selections can round-trip as existing InitChoices without schema changes. Planning a JSON/config choice may inspect only explicitly supplied additional paths under this same policy; do not require a prior in-memory UI session for valid explicit config input. Unknown arbitrary paths must never be accepted merely by adding them to a list. Noninteractive paths stay prompt-free. Existing normal init reuse remains unchanged without --reconfigure.

Existing exclusions, nested workspace boundaries and repository ownership/symlink rules remain in force. A directory addition does not imply exhaustive subtree scanning or verified registration. Preserve existing configured values and never fake observed repositories/documents to bypass the app validator.

Repository addition must resolve the exact existing checkout rather than silently substitute a parent repo. Respect current .git, worktree/external/symlink and nested-workspace rules. Preserve IDs/access of existing repositories and original-checkout validation binding. No outside-workspace checkout may become a local repository by an alias.

Use a small app-layer bounded inspection/selection helper shared by UI and plan, not another discovery framework or persisted draft format. Keep observations explicit and read-only.

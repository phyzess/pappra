## P1: uncertain delivery is retried and retry authority goes stale

`performWithRetry` converts every controller exception to `failed/none`, then retries it. A controller that enqueues and then loses the connection is called three times (expected once, unknown thereafter). The concrete Herdr controller repeats the same unsafe conversion. Disposition alone cannot prove absence of effects; a supplied failed result with queued/applied observation must also never retry. Retry only explicit supported evidence of known no effect. Persist each dispatch intent and confirmed outcome/retry budget before the next attempt; the present implementation only records the final result and has no durable per-attempt journal.

A CANCEL admitted during injected backoff also produces three controller calls (expected one). Revalidate current task namespace/record/plan digest, actor/attempt/input/epoch/approval/cancellation/claims and live target immediately before every attempt after backoff. A throw or ambiguous observation must stop as unknown. Strictly bound and validate numeric retry inputs, including NaN/infinity. Keep backoff local and bounded, with no workflow completion polling.

## P1: native destination and acting host are configuration assertions

`herdrRecoveryController` ignores `request.target` and prompts arbitrary configured `target.agent` without `verifyCaller`, live agent/session/cwd checks or task-bound routing validation. `expectedSession.cwd` and `binding_digest` are never used by `validateIdentity`. The Pi extension ignores actual event context, comparing configured self to configured expected instead. Loading the config in another session can therefore wake the configured agent. The CLI calls this a verified transport despite no live verification.

Use actual supported Pi host facts at each event/manual boundary, and an explicit task binding with pinned digest plus live Herdr participant/session/cwd verification before dispatch. Reject missing/mismatched evidence without fallback or fresh process. Keep model/provider mutable. The completed-result review actor is the current coordinator: do not compare the coordinator session to the completed writer's `attempt.native.session_id`; verify actor and recipient according to the selected role/action. Add real bound-native writer/report coordinator tests, wrong-target/cwd/binding tests and an extension loaded in a foreign actual session. Do not synthesize host facts or use casts to bypass supported SDK APIs.

## P1: sidecar writes escape through an existing symlink

Precreate `<taskRoot>/.recovery` as a symlink to an outside directory. `executeRecovery` creates `outside/reservations`, writes the reservation/outcome there and issues a wake (observed controller calls=1). Task/messages namespace anchoring does not cover this new subtree. Anchor and no-follow-check all sidecar parents/files before and around read/create/update/effect boundaries, retain the initial task namespace anchor across the entire operation, and refuse redirects/replacements before effects or outside writes. Reservation parsing must validate the complete bounded structure and return a structured unknown for corrupt/truncated data rather than dereference an absent `cause`. Use durable exclusive intent and safe outcome persistence with appropriate fsync; do not claim an OS atomic fence or cross-process exactly-once guarantee.

## P1: caller-generated request IDs bypass cause deduplication

Two identical unchanged recovery recommendations with `requestId=req-1` then `req-2` issue two wakes. The reservation key hashes action key plus request ID, so deduplication does not protect the durable cause across restarted/manual callers. Use a canonical cause identity containing task/actor/role/attempt/input/epoch and admitted ANSWER/REPORT identity as appropriate; request ID should correlate callers, not create another right to send. Distinguish legitimate later causes from replay, preserve ambiguous intents, and add truly concurrent calls (the supplied test labeled concurrent only performs sequential calls). Persist retry outcomes and intentional reconciliation rather than adding TTL stealing or a scheduler.

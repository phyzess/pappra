## Outcome

Users can identify their workspace and selected repositories, distinguish existing knowledge sources from the destination for new documents, understand privacy defaults, preview actual side effects, correct choices, and see accurate completion and next steps.

## Confirmed findings

1. Task pin writes and removals can follow redirected private-state parents outside the workspace.
2. Pin accepts 128-character task identifiers while continuity accepts only 64.
3. Quoted Git porcelain filenames omit untracked document bodies and body changes from checkpoint payloads.
4. Unresolved configured repositories can disappear from checkpoints while resume reports current verification; newly present repositories are not compared.
5. Knowledge scan discards discovery failures and truncation diagnostics.
6. Existing documents registered with the default private policy disappear from the default list without adequate explanation.
7. Interactive reconfiguration skips editing and can incorrectly report that valid configuration is missing.
8. Runtime installation occurs after a confirmation that describes external actions as pending.
9. Wizard defaults are invisible before submission; path validation happens after all choices.
10. Knowledge files and ancestor directories appear as a flat overlapping list with insufficient scope explanations.
11. Basic setup asks advanced questions before users understand the resulting capabilities; internal milestone names leak into prompts.
12. Human summaries and entry points use inconsistent completion language and incomplete help.

## Decisions and compatibility

- First fix reliability; then restructure configuration and interaction.
- Before extending implementation, audit the maintained legacy collaboration workflow against packaged instructions, public CLI/MCP/API, runtime adapters, recovery, and tests. Recover reusable existing primitives; do not replace the workflow with another narrowed scheduler/controller.
- Use a shared continuity/task-pin identifier rule with a maximum of 64 characters; invalid IDs fail before mutation. Preserve the separate legacy collaboration task identifier contract (up to 128 characters); do not shorten valid existing collaboration IDs under this fix.
- Never grant execution from a checkpoint; preserve existing advisory authority restrictions.
- Preserve existing document visibility. Keep private defaults; sharing requires an explicit choice.
- Prefer improving `init --reconfigure` before introducing another configuration command.
- Separate configured, installed/bound, prepared/registered, and verified observations by capability; unselected optional capabilities are not failures.
- Default choices must be shared between interactive and derived setup, with intentional differences explained.
- Preserve existing JSON contracts. Additive observations require compatibility tests; semantic wire changes require an explicit schema decision.
- Prefer existing filesystem, lock, journal, and ownership helpers over another state-management framework.
- Tests assert meaningful behavior and cancellation/side-effect boundaries, not every exact copy string.
